# On-policy VLM/LLM distillation lab

This subsystem trains the VLM grounding policy and the chat/planning LLM from
rollouts generated by the **current** student policy. A multimodal teacher scores
each transition and returns a closed-schema target. The student is updated
immediately; samples whose `policy_version` exceeds the configured lag are
rejected.

## What is implemented

- a reproducible Android/custom-OS emulator manifest;
- a normalized-document curriculum builder;
- snapshot-bounded documentation coverage accounting;
- strict multimodal teacher contracts;
- discounted on-policy advantages;
- supervised action targets, policy loss, box regression, language loss and KL;
- real NumPy checkpoint updates for CI;
- optional PyTorch/PEFT adapters for actual VLM and LLM weights;
- dry-run, replay and plugin-backed training modes.

No model weights, custom-OS images, API keys or proprietary SDKs are committed.

## Emulator matrix

`config/emulator_matrix.json` contains 9 base profiles and 66 expanded
screen/locale/navigation variants:

| Family | Profiles |
|---|---|
| AOSP/Google APIs | Android 10 low-end phone; 12L resizable; 14 mainstream phone; 15 high phone; 16 tablet; 17 foldable |
| GrapheneOS | pinned Android 17 `sdk_phone64_x86_64-userdebug` source build |
| CalyxOS | pinned manifest `sdk_phone64_x86_64-userdebug` source build |
| /e/OS | approved Android 13 x86_64 image with Nexus 5X AVD profile |

The custom-OS profiles are disabled by default. They become runnable only after
the source revision or image artifact is pinned, licensed, hashed and made
available to the lab. AOSP is never silently substituted for a missing ROM.

The emulator matrix is for functional rollout and dataset diversity. Hardware
security, OEM drivers, NPU delegates, thermals and real touch timing still need
physical-device validation.

## Documentation coverage contract

"Full documentation coverage" is deliberately finite and auditable:

1. discovery runs against an approved source registry;
2. every document is pinned to a Git commit, revision or immutable content hash;
3. every discovered section is normalized;
4. each section ends as `validated`, `non_actionable` or `blocked`;
5. required document classes must be present for every source;
6. a changed upstream revision makes the ledger stale and fails the gate.

This does **not** claim coverage of future pages, undiscovered documents or
settings unsupported by the selected emulator artifact.

The current registry covers AOSP Settings APIs/source, GrapheneOS official
documentation/source, CalyxOS documentation/source and /e/OS documentation.
It follows the repository's ORM rule that documents are evidence, not executable
instructions.

## Teacher profiles

### `flux3_early_access`

FLUX.3 is represented as a provider-neutral Early Access profile. The checked-in
configuration has no endpoint/model and `early_access_acknowledged=false`.
Training cannot contact it until all of the following are explicitly supplied:

- an approved HTTPS endpoint and exact model identifier;
- an allowlisted host;
- an API-key environment variable;
- acknowledgement of the Early Access contract;
- a transport adapter matching the actual response protocol.

The code does not invent a public FLUX.3 evaluator API.

### `openai_compatible`

Uses the same closed teacher schema with a configured endpoint. The name refers
to request transport shape only and does not require an OpenAI model.

### `replay`

Offline deterministic teacher for CI and reproducible regression tests.

## Teacher response schema

The teacher may return only:

```json
{
  "confidence": 0.0,
  "scores": {
    "total": 0.0,
    "grounding": 0.0,
    "planning": 0.0,
    "language": 0.0,
    "safety": 0.0
  },
  "should_update": true,
  "target": {
    "kind": "tap",
    "target_label": "Bluetooth",
    "bbox_norm": [0.1, 0.1, 0.5, 0.2],
    "response": "Tap Bluetooth"
  },
  "tags": []
}
```

Unknown fields, malformed boxes, low-confidence judgements and executable text
such as ADB/Accessibility commands are rejected. Chain-of-thought is neither
requested nor stored.

## Training real weights

The default NumPy student proves that rollout batches change weights and produce
checkpoints in CI. Production training should supply:

- `--student-plugin module:factory`, returning a student policy and updater;
- `--environment-plugin module:factory`, returning an emulator environment;
- model-specific image/token preprocessing;
- either `TorchOnPolicyUpdater` or `JointTorchVlmLlmStudent`;
- PEFT/LoRA target modules where full fine-tuning is impractical.

The joint PyTorch loss is:

```text
supervised action CE
+ advantage-weighted on-policy loss
+ VLM bounding-box regression
+ LLM token cross-entropy
+ reference-policy KL
```

## Shipped project plugins

`project_train:create_student` and `project_lab:create_environment` are the
reviewed reference implementations used by the documented commands.

### `project_train` — Qwen2.5-1.5B-Instruct speedrun-LoRA student

The student is the text-only `Qwen/Qwen2.5-1.5B-Instruct`. It reasons over the
accessibility labels and the normalized OS-settings evidence embedded in the
task (screenshots stay with the multimodal teacher) and emits one closed JSON
action per step. The action distribution is the softmax over the six proposal
kinds at the forced `"kind"` token position, so every proposal carries a real,
normalized distribution and log-probability.

The updater reproduces the lora-speedrun Track-1 record
(`submissions/003-pmigdal`, 1m 44s to 60.3% GSM8K on Qwen2.5-1.5B):

- LoRA r=16, alpha=32, dropout=0.0 on all seven linear projections
  (18,464,768 adapter parameters);
- AdamW (fused on CUDA), betas (0.9, 0.95), no weight decay, LR 4e-4, 8-step
  warmup, cosine decay to 5%;
- greedy packing of teacher completions into full fixed-length blocks that are
  moved to the device once (no dataloader, no collation, no attention mask);
- completion-only cross-entropy via a chunked custom autograd function, so the
  full fp32 logits tensor is never materialized.

The repository loss terms map onto the text-only student as follows: the
supervised action CE and the advantage-weighted policy term read logits at the
kind-token position; box supervision is the cross-entropy over the teacher
`bbox_norm` token span; the language term covers the whole teacher completion;
the reference-policy KL compares against the frozen base model with LoRA
adapters disabled. Samples whose teacher judgement has `should_update=false`
(e.g. teacher/critic disagreement) never move weights.

Optional `student_config` keys: `model_id`, `device`, `dtype`,
`max_new_tokens`, `seed`, `lora` and `speedrun` overrides.

### `project_lab` — adb emulator environment

The environment attaches to a running emulator (or boots a matching AVD with
`ANDROID_DRLQN_LAB_AUTOBOOT=1`), launches the Settings app and captures
timestamp-aligned observations: a PNG screenshot under
`artifacts/lab-screenshots` (inside the teacher's allowed image roots) and the
uiautomator hierarchy for labels, bounds and the accessibility summary.

Safety contract mirrors `AdbResearchActuator`: input injection requires
`ANDROID_DRLQN_ALLOW_EMULATOR_INPUT=1` and a positive emulator check
(`ro.kernel.qemu` / build characteristics). Taps resolve from the proposal's
`bbox_norm` (times the live display size) or from the target label's
uiautomator bounds. A transition is verified when the task's expected setting
label is visible after the action; language turns (`explain` /
`ask_confirmation`) are terminal on-device and left to the teacher to score.

## Commands

Dry-run the curriculum and matrix without loading a teacher:

```bash
python scripts/train_on_policy.py \
  --documents artifacts/normalized-documents.json \
  --config config/distillation.json \
  --dry-run
```

Replay smoke training:

```bash
python scripts/train_on_policy.py \
  --documents artifacts/normalized-documents.json \
  --config config/replay-distillation.json \
  --fixture tests/fixtures/distillation_environment.json
```

Check a completed coverage ledger:

```bash
python scripts/check_document_coverage.py artifacts/distillation/coverage.json
```

A release must not claim documentation completeness unless this gate passes for
the exact pinned revisions and selected emulator artifacts.
